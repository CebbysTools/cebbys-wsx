# Fork patches

Fork-only file. Every change this fork makes to AnyPS5 is listed here, one row per feature branch.
Upstream's conventions check rejects this file; never include it in a branch meant for upstream (AGENTS.md section 9).

## Rules

- One patch = one feature branch from `upstream/main` (`feat/...`, `fix/...`, `perf/...`), Conventional Commits, upstream rules (CONTRIBUTING.md).
- Add the row when the branch is created; update **Status** and **Evidence** as it moves.
- `nhl27` is the integration branch: `main` plus every branch below with status `testing` or later, merged for game runs. Rebuild it after any patch branch changes:
  `git checkout nhl27 && git reset --hard main && git merge --no-edit <branches...>`
- Game-side byte patches (relinker `--patches` TOML files) are tracked in the second table; their files live in `fork-patches/`.
- Branches start from the upstream commit the fork is based on (currently `9a97ac784`), never from the fork's `main`, so their diff holds only the patch. Diagnostic branches (`diag/...`) are never merged into `nhl27` permanently or sent upstream.
- Status values: `testing` (in `nhl27`), `ready` (conventions check and tests pass), `upstream-pr #N`, `merged`, `dropped` (say why).

## Running NHL 27 with the fork

Plan to reach 144 Hz: milestone `perf-jvvo` in beans (`beans list --tag nhl27-perf`), research in [fork-notes/MILESTONE_144FPS_RESEARCH.md](fork-notes/MILESTONE_144FPS_RESEARCH.md).

Why it runs at 1-2 FPS and what the driver needs: [fork-notes/AGC_DRIVER_PERFORMANCE.md](fork-notes/AGC_DRIVER_PERFORMANCE.md).

Environment: `ANYPS5_OUTPUT_RESOLUTION=2160p` (required). Do not leave diagnostic `APS5_*` switches set: the shader cache key includes them, so each new combination recompiles every shader (~26,000, ~40 GB).

Known state (2026-10-21): boots, passes the licence screen, reaches the quick-settings menus at 1-2 FPS. Frame time is dominated by compute shaders the recompiler expands to ~85% float-semantics emulation (NaN-aware min/max/med3, software denormal flush); NVIDIA compiles the largest to 255 registers with ~2 KB per-thread local memory. Ruled out for the slow compute program 0x115258a000 (~340 ms per frame, SPIR-V under 100k words): float emulation (`APS5_FAST_FLOAT`), f16 NaN fix-ups, guest memory over PCIe (`APS5_NO_HOST_IMPORT`), runaway loops (`APS5_LOOP_GUARD=2000` never trips). Nsight Graphics 2026.3.1 GPU trace (2 frames, menus, 2026-10-21): GPU frame 412 ms, SM throughput 10% of peak, compute warps active 20%, warp launches stalled on register allocation (651M cycles compute, 877M pixel), average compute warp latency 53k cycles, top issue stall `long_scoreboard` on L1TEX, 1.8 GB PCIe writes. The slow program itself is 96 registers without spills, so the next step is the real-time shader profiler on it (needs GPU counters: admin, or the NVIDIA "allow access to GPU performance counters to all users" setting). Run traces with `C:\Users\valen\anyps5-toolchain\trace.cmd` from an elevated context; do not pass `--platform` (Qt takes it as its own option). Build `nhl27`, copy `build/core/libs/libs/*.prx` and the WinLibs runtime DLLs to `libs/`, relink `eboot.elf` with the same build's relinker.
